# Brief: redesign the chess web UI in the spirit of chess.com (mobile and desktop)

You are redesigning the web UI of chess-mcp, an app where one person plays chess against Claude for
self-improvement. The backend is done. You own the whole front end and may rewrite it freely:
`src/chess_mcp/web/index.html`, `src/chess_mcp/web/app.js`, `src/chess_mcp/web/style.css`. Touch nothing else.
No build step, no npm, no frameworks: plain HTML, one ES module, one stylesheet. Libraries only from CDN as now
(chessground 9.2.1 for the board; keep its cburnett pieces). Everything else you write yourself.

Model it on chess.com's game screen (web and the mobile app) as the reference for layout, density, colour and
feel: dark charcoal surfaces, the green-and-cream board, bold readable type, rounded cards, player bars with
avatar circles, a two-column move list with the current move highlighted, a bottom tab bar on phones, the
"Game Report" look for reviews (accuracy circles, eval graph with classification icons, rating counts table).
Do not copy their logos, names or assets; do copy the structure and polish. Default to the dark theme; keep a
light theme via `prefers-color-scheme`.

## Non-negotiables

1. **Protocol.** The server's WebSocket protocol below is fixed. Every message type and state field must be used
   exactly as described. Send with `JSON.stringify`, receive JSON. Reconnect with backoff on close; a close code
   4401 means a wrong password.
2. **Fits one phone screen.** On phones (width ≤ 860px) the Play screen must show, with NO page scrolling:
   opponent bar, board, your bar, the move strip, status/banner, action buttons and the bottom tab bar. Use
   `100dvh`, size the board to the remaining height, respect `env(safe-area-inset-*)`. Keep the viewport meta
   `width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=resizes-content`, and when the
   on-screen keyboard opens the chat input must remain visible (the chat sheet takes the remaining height).
3. **Desktop.** ≥ 861px: board with player bars on the left, a right panel with tabs (Moves, Chat, Review) and
   the game actions at the panel's bottom, like chess.com's web layout. Max content width about 1200px.
4. **Live updates must not clobber input.** State messages arrive several times a second during a game (eval
   updates). Re-render from state, but never reset what the user is typing in the chat or the password or the
   sign-in code, and never reset scroll positions the user is reading, unless new content arrived.
5. **Accessibility.** Every control labelled; dialogs/sheets trap focus and close on Escape; `aria-live` for
   status; 44px touch targets on phones; respect `prefers-reduced-motion`.
6. **Tests.** The served page must contain the strings `chessground@9.2.1` and `/static/app.js`, and
   `/static/style.css` must exist. `node --check` must pass on `app.js`.
7. You cannot open a browser. Re-read your diff for syntax errors. A reviewer will test it in a real browser
   and send you screenshots with corrections; expect a second round.

## Features to build

### Gate (password)
Centred card: title, "Enter the password to play.", a `type="password"` input (`autocomplete=current-password`),
Continue. The password is sent as the `token` query parameter on the WebSocket and stored in
`localStorage['chess-token']`. A `?token=...` in the page URL (links Claude shares) is stored and stripped
from the URL. On close code 4401 show "Wrong password. Try again." and clear the stored value.

### Play screen
- Player bars: avatar circle (♞ for Claude, a plain circle for you), name ("Claude" / "You"), and for Claude
  the difficulty label (e.g. "1500" or "Claude" when no target), a small "offline" pill when
  `claude_connected` is false, and in review mode each side's accuracy.
- Board: chessground, coordinates on, last move and check highlights, legal-move dots, drag and click moves,
  promotion picker overlay, **premoves** (chessground `premovable`): when it's not your turn you may set a
  premove; when your turn arrives, send it if it is legal (`dests`), else clear it. Optional eval bar beside the
  board (toggle, persisted in localStorage `chess-eval`).
- Move strip (phones): a horizontal, auto-scrolling strip of moves under the board with the latest highlighted;
  tapping a move in a finished/review game steps to it. On desktop the Moves tab shows the two-column list.
- Status line: "Your move" / "Claude is thinking…" / game result text / Claude runner messages (below).
- Banner cases, in priority order: Claude offers a draw (Decline / Accept); game over (result + "Review" button);
  hosted Claude not running (text + "Start Claude" or "Sign in" button; see runner states).
- Action buttons: New game, Offer draw, Resign (confirm), Flip, Eval bar toggle, Sound toggle (persisted in
  localStorage `chess-sound`), Past games.
- Sounds: synthesise with the Web Audio API (no audio files): move, capture, check, game end, chat received.
  Different, short, tasteful. Never play before the first user interaction.
- Animations: chessground piece animation (160ms; 0 under reduced motion), sheet slide-up, tab transitions,
  banner fade, rating badge pop in review. Keep it quick (≤ 200ms).

### Bottom tab bar (phones)
Play · Review · Chat · More. Play is the board screen. Review opens the game report (if the current game is
over or a past game is being reviewed; otherwise a short "Finish a game to review it" screen with the past
games list). Chat opens the chat sheet over the board with an unread dot when Claude wrote while it was
closed. More opens a settings sheet: Claude settings (account, model, start/stop), Difficulty, Past games,
Sound, Eval bar, Flip board.

### New game dialog
Choose side (White / Random / Black, with piece glyphs) and difficulty: presets Beginner 1320, Casual 1500,
Club 1800, Strong 2200, Expert 2600, Master 3000, and "Claude" (no target: Claude plays its own game), plus a
slider from 1320 to 3190 in steps of 10 that the presets snap to. Starting a game sends
`{"type":"new_game","human_color":"white|black|random","elo":1500}` (`elo` null for "Claude"). If a game is
active with 2+ moves, confirm "Resign this game and start a new one?" and send `resign` first.
Changing the difficulty outside a new game sends `{"type":"set_difficulty","elo":1500|null}`.

### Chat
Bubbles (Claude left, you right), timestamps optional, auto-scroll when near the bottom, input with send
button; Enter sends. `{"type":"chat","text":"..."}`. Unread dot logic as above.

### Review ("Game Report")
Available after a game ends (banner "Review") and from Past games. Opening it sends
`{"type":"open_review","game_id":"..."}`; the server streams `review_progress` then `review`. Show a progress
bar while analysing. The report: accuracy circles for You and Claude, the eval graph (`eval_series`: white
win % per position, 0..100; draw a filled area, a midline, a cursor at the current ply, and classification
dots for key moves), the rating counts table (both sides), and the move list with a badge per move. Stepping:
first/prev/next/last buttons, ← → Home End keys, swipe on the board, tapping moves or the graph. For the
current move show its badge, label (e.g. "12. Nf3"), rating name, eval after, and the best line when the move
wasn't best (also draw a green arrow for the best move). Closing returns to Play.
Ratings and their chess.com-like colours/glyphs: brilliant (teal, "!!"), great (blue, "!"), best (green,
"★"), excellent (green, "✦"), good (light green, "✓"), book (brown, "≡"), inaccuracy (yellow, "?!"),
mistake (orange, "?"), miss (red-orange, "✕"), blunder (red, "??").

### Claude settings (hosted Claude)
Account: signed in as email / Sign out, or "Sign in to Claude" (`claude_login`); while `login.busy`: the
sign-in link (`login.url`, new tab; "Preparing…" while null), a code input + Continue (`claude_login_code`),
Cancel (`claude_login_cancel`); "Checking the code…" while `login.verifying`. Model select from `models`
(`claude_model`). Status (stopped/starting/running/stopping/error + `error` text) and a Start/Stop button
(`claude_start` / `claude_stop`; Start disabled unless signed in). If `claude.available` is false, explain
that Claude Code isn't installed on the server and hide the controls. Runner status texts when
`claude_connected` is false: starting → "Claude is starting…", running → "Claude is connecting…",
stopping → "Claude is stopping…", error → "Claude stopped: {error}", stopped → "Claude isn't running." or
"Sign in to Claude to play." when not signed in; when `available` is false → "Claude isn't connected. Ask
Claude to play chess in Claude Code."

### Past games
`{"type":"list_games"}` → `games` message. Rows: result (Won/Lost/Draw), opening or move count, difficulty
(`elo` or "Claude"), date; tap to review.

## The protocol (fixed)

Connect: `ws(s)://<host>/ws?token=<password>`. Server → browser messages:

- `state` (sent on connect and on every change; `seq` increases, drop any with `seq <= last seen`):
  `game_id, fen, turn ("white"|"black"), human_color, moves: [{san, uci}], last_move: [from,to]|null,
  check: bool, dests: {from: [to,...]} (only on your turn), status: "active"|"checkmate"|"resigned"|
  "draw_agreed"|"stalemate"|"insufficient_material"|"threefold_repetition"|"fivefold_repetition"|
  "fifty_moves"|"seventyfive_moves", result, reason, winner: "white"|"black"|null, draw_offer:
  "human"|"claude"|null, chat: [{id, sender: "human"|"claude", text, at}], claude_connected: bool,
  eval: {win_white: 0..100, text: "+0.35"}|null, elo: int|null (this game's difficulty),
  difficulty: {elo: int|null, min: 1320, max: 3190} (the setting for new games),
  claude: {available, status, model, models: [{id,name}], error, auth: {logged_in, email},
  login: {url, busy, verifying}}`
- `error`: `{code, message}` → toast. Codes include not_your_turn, illegal_move, game_over, bad_model,
  claude_not_signed_in, claude_busy, claude_unavailable, no_login, bad_elo.
- `games`: `{games: [{game_id, started_at, ended_at, human_color, result, winner, reason, opening, moves, elo,
  reviewed}]}` (timestamps are unix seconds).
- `review_progress`: `{game_id, done, total}`.
- `review`: `{review}` where review = `{game_id, opening, white: {name, accuracy, counts: {rating: n}},
  black: {...}, eval_series: [..], moves: [{ply, color, san, uci, fen, rating, eval_after, win_white_after,
  best_uci, best_line}]}`. The human side is the one whose `name` is "Human" (older reviews say "You"); the
  other is "Claude".

Browser → server: `move {move: "e2e4" | "e7e8q"}`, `chat {text}`, `new_game {human_color, elo?}`, `resign`,
`offer_draw`, `answer_draw {accept}`, `list_games`, `open_review {game_id}`, `set_difficulty {elo}`,
`claude_start`, `claude_stop`, `claude_model {model}`, `claude_login`, `claude_login_code {code}`,
`claude_login_cancel`, `claude_logout`.

When done, print a summary: the screens, how state maps to them, and anything you were unsure about.
